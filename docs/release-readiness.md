# Release Readiness

Recorded for the TerritoryKit `2.0.0` stable handoff on 2026-08-22 and updated after the
Changesets Version Packages PR. This state has versioned package manifests but still does not imply
that npm packages, a Git tag, or a GitHub Release have been published.

## Decision

Decision: versioned release state is ready for the guarded release workflow once CI is green.

Publishing remains controlled by `.github/workflows/release.yml`. The release-hardening PR and
Changesets Version Packages PR have moved the fixed core family to `2.0.0`; maintainers should
verify CI and npm Trusted Publishing settings before treating the release as complete.

## Evidence

The branch evidence is generated by `pnpm release:hardening`:

- `docs/release-artifacts/production-hardening-report.json`
- `docs/release-artifacts/license-inventory.prod.json`
- `docs/release-artifacts/turkey-adm2-benchmark.json`
- `docs/release-artifacts/release-fixture-benchmark.json`
- `docs/release-artifacts/checksums.json`

The ADM2 production evidence is pinned in
`benchmarks/evidence/turkey-adm2-production.json`. A clean checkout verifies its SHA-256,
source-lock identity, dataset version, 973-feature count, and recorded production benchmark against
the unchanged production budget. It also runs and compares a 2,500-feature deterministic fixture
benchmark against the current code. The hardening report labels this mode
`pinned-evidence-and-current-fixture`; it does not claim that a fresh production benchmark ran.
If the ignored ADM2 dataset is present, or `TERRITORYKIT_BENCHMARK_DATASET` names one, its bytes,
identity, version, and feature count must match the pin before a fresh local-real benchmark runs.
An explicit missing path or a mismatched file fails hardening. Existing local Turkey artifacts are
checksum-validated when present; a clean checkout uses the pinned reviewed Turkey evidence and
labels that provenance in the report. National geometry is never regenerated by this command.

## Manual Publish Steps

1. Confirm the fix PR for the post-Changesets state is green.
2. Verify package versions, package changelogs, tarball dry-run output, and npm Trusted Publishing
   settings.
3. Let the guarded release workflow publish when no Changesets remain, or dispatch it from `main`
   according to maintainer policy.
4. Verify npm package pages, provenance, package exports, registry smoke tests, and final release
   notes.
5. Create a Git tag or GitHub Release only after npm and registry verification succeeds.
